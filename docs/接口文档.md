# WowsApi 接口文档

> 面向 `wows-api`（jar 2.5.x）当前已实现的官方接口。
> 文档里的字段清单来自**真实响应**（国服账号 `7060948811`、亚服账号 `2022515210` 等），
> 与代码中的结构体一一对应；字段漂移由 `SchemaMonitorTest` 监视（见文末）。

## 1. 总览

### 1.1 通道

| 通道 | 域名 | 请求类 | 说明 |
| --- | --- | --- | --- |
| 官方开发者API | `api.<server>` | `ApiHttp` | WG 官方 API，需要 `application_id`（莱服用 `/mk/` 前缀 + 307 握手，由 `HttpTransport` 自动处理 cookie 与重定向） |

服务器枚举 `WowsServer`：

| 枚举 | code | 域名后缀 | 支持官方API |
| --- | --- | --- | --- |
| CN | cn | wowsgame.cn | 否 |
| ASIA | asia | worldofwarships.asia | 是 |
| EU | eu | worldofwarships.eu | 是 |
| NA | na | worldofwarships.com | 是 |
| RU | ru | korabli.su | 是 |

`server.api()` 给出官方开发者API 的域名。

### 1.2 入口类

| 类 | 覆盖范围 |
| --- | --- |
| `WowsHttpUserTools` | 账号：详情、搜索（官方） |
| `WowsHttpShipTools` | 战舰：统计、战绩、徽章（官方） |
| `WowsHttpClanTools` | 军团：详情、搜索、赛季（官方） |
| `WowsEncyclopediaTools` | 官方词典（glossary） |

### 1.3 通用约定

- **隐藏战绩**：接口返回 `hidden_profile=true` 时抛 `HiddenProfileException`。
- **超时**：全部走 `HttpCodec.requestTimeout()`（默认 3 秒，`HttpCodec.updateTimeout(int)` 修改）；`HttpCodec.client()` 是全局共享的 `HttpClient`（连接池复用、不跟随重定向、不挂 CookieHandler，重定向/Cookie 由 `HttpTransport` 按主机处理）。
- **压缩**：请求只声明 `gzip, deflate`，`HttpCodec.response` 负责解压与状态码校验——它是所有响应的唯一解码出口。
- **缺字段容错**：Jackson 3 的 `asXxx()` 在字段缺失/null 时抛异常，库内统一用带默认值的重载，接口新增字段不会导致解析失败。
- **时间字段**：返回的时间多为 ISO 字符串（如 `2026-06-15T11:21:44.918201`）或 Unix 秒；结构体保留原始形态（`String`/`double`），需要毫秒时间戳时用 `DateUtils`。

## 2. 官方开发者 API

### 2.1 接口清单

| 接口 | 调用 | 返回结构 |
| --- | --- | --- |
| `GET /wows/account/list/?search=`（莱服 `/mk/`） | `new WowsHttpUserTools(client, server).searchUserDevelopers(token, name)` | `List<DevelopersSearchUser>` |
| `GET /wows/account/info/?account_id=&extra=` | `...accountInfoDevelopers(token, accountId)` | `AccountInfo` |
| `GET /wows/account/info/`（精简） | `...userInfoDevelopers(token, accountId[, accessToken])` | `DevelopersUserInfo` |
| `GET /wows/ships/stats/?account_id=&extra=` | `new WowsHttpShipTools(client, server, accountId).developers(token).shipList()` | `DevelopersUserShip` |
| `GET /wows/ships/stats/`（全量战绩） | `...developers(token).shipOperList()` | `DevelopersUserShipOper` |
| `GET /wows/ships/badges/?account_id=` | `...developers(token).shipBadges()` | `Map<Long, ShipExpansion>` |
| `GET /wows/clans/info/?clan_id=&extra=members` | `new WowsHttpClanTools(client, server).developers(token).clanInfoDevelopers(clanId)` | `DevelopersClanInfo` |
| `GET /wows/clans/list/?search=` | `...developers(token).searchClanDevelopers(tag)` | `List<DevelopersSearchClan>` |
| `GET /wows/clans/accountinfo/?account_id=&extra=clan` | `...developers(token).userSearchClanDevelopers(accountId)` | `DevelopersSearchUserClan` |
| `GET /wows/clans/season/?language=zh-cn` | `...developers(token).season()` | `List<DevelopersSeasonInfo>` |
| `GET /wows/clans/glossary/`（莱服 `/mk/clans/glossary/`） | `new WowsEncyclopediaTools(client, server).developers(token).glossary()` | `DevelopersGlossary` |

各工具的 `xxxUri()` 方法可以直接拿到 `URI`（便于自建请求或做异步）。

## 6. 两条通道对照：`ShipInfo`

战舰数据有两条通道，最终都转成 `ShipInfo`：

| | vortex | 官方开发者API |
| --- | --- | --- |

### 6.3 用 `ShipInfoSource` 判断字段是否可用

`ShipInfo` 自带来源标记 `source()`（`VORTEX` / `DEVELOPERS` / `MIXED` / `UNKNOWN`），并提供可用性判断：

```java
if (info.hasBasicXp()) {            // 官方API 侧为 false，"0"只代表没有这个数据
    sum += info.basicXp();
}
info.hasDbomb();          // 深水炸弹数据
info.hasOtherHitRatio();  // 深弹/炸弹/火箭/跳弹命中
info.hasLastBattleTime(); // 最后战斗时间
info.hasExpansion();      // 精通徽章
```

聚合（`addition` / `subtraction`）只有**同源**才保留来源，**跨来源自动退化为 `MIXED`**，
上面前提一律返回 false —— 避免"一半是 0 的合计"被当成真实数据。

### 6.4 纪录保持战舰

`MaxInfo.MaxShipInfo.shipId` 现在取"创造该纪录的战舰"：vortex 用 `max_*_vehicle`、
官方API 用 `max_*_ship_id`（武器类在各自的 `main_battery`/`torpedoes`/... 子块里）；
单船数据里这些值为 0（纪录就是本条船）时回退到当前 `shipId`。

## 7. 兼容性与序列化约定

### 7.1 数据模型的版本兼容（Java 原生序列化，已实测）

| 变更 | 结果 |
| --- | --- |
| record **加**字段 | ✅ 旧数据可读，新字段取默认值（null/0） |
| record **删**字段 | ✅ 旧数据可读（多余字段被跳过） |
| record **改字段类型** | ❌ `InvalidClassException: incompatible types for field xxx` |
| 改包名/类名、record ↔ 普通类互转 | ❌ ClassNotFoundException / 不兼容 |

- **record 的默认 `serialVersionUID` 恒为 0L**（不是普通类的结构哈希），所以「加字段」天然兼容 → record 里**不要**手写 `serialVersionUID`（手写反而会把「改类型」这种真不兼容变成静默）；
- **普通类一旦 `implements Serializable` 必须显式声明 `serialVersionUID`**，否则加字段就会让旧数据读不出来。目前库里实现 `Serializable` 的只有 8 个 record（`ShipInfo`/`Battle`/`FragsInfo`/`MaxInfo`/`MaxShipInfo`/`HitRatio`/`ControlCapturedAndDroppedPoints`/`ShipExpansion`）与 `WowsBattlesType` 枚举，没有 `@Data` 普通类，所以暂时没有这个雷；
- 读取端要能容忍「新字段为默认值」：`ShipInfo` 的 `source` 在旧数据里不存在，紧凑构造器会归一为 `ShipInfoSource.UNKNOWN`（最保守，`hasXxx()` 全 false），Jackson JSON 缺字段同样适用；
- 长期缓存/跨进程传输建议用 **JSON**（`JsonUtils`），Java 原生序列化只当「同版本内短期缓存」；
- 需要跨大版本读旧缓存时，再考虑序列化代理（`writeReplace`/`readResolve`）或一次性迁移工具，目前不做。

### 7.2 源码/二进制兼容

- 2.6.0 起多处 record 加了字段（vortex / dev / `ShipInfo`），**直接 `new` 这些 record 的下游代码**需要跟着调整（源码级编译失败；已编译的二进制会 `NoSuchMethodError`）；用库的 `parse(...)` / `to(...)` 工厂方法不受影响；
- 下游自己 `new` 的代码建议尽早换成工厂方法。

### 7.3 回归测试

## 8. 莱服(korabli.su)差异（2.7.0）

两家分家后，莱服的域名、路径、字段集都和 WG 那边不一样了。这里记的是 **2026-10-10 用账号 212112137 / 军团 451731 实测**的结论。

### 8.1 域名与路径

| 通道 | 其它服 | 莱服 |
| --- | --- | --- |
| vortex | `vortex.worldofwarships.<tld>` | `vortex.korabli.su` |
| vortex(公开测试) | `vortex.worldofwarships.pt` | `vortex-rpt.korabli.su` |
| clans | `clans.worldofwarships.<tld>` | `clans.korabli.su` |
| 官方API | `api.worldofwarships.<tld>/wows/...` | `api.korabli.su/mk/...` |

只有账号/战舰/词典走 `/mk/`。
