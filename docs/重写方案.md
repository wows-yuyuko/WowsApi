# WowsApi 3.0 重写方案（草案 v0.1）

> 状态：已评审并执行中 —— **Phase 0 / Phase 1 / Phase 2 已完成**（分支 `rewrite/3.0`，执行记录见 §11）；
> 行为对照表见 `docs/重写Phase0-行为对照表.md`。
> **已锁定**：3.0 断代（不保留兼容层）；凭证按服务器区分，dev / vortex token 分离，预留 cookie 类认证。
> 基准事实（本机实测）：现 main 134 个 java 文件 / 约 296KB；请求调用点 33 处、`URI.create` 构造点 40 处——这 40 处散落就是本方案要消灭的对象。
> （复查：业务代码请求发送点实测 29 处，聚合为 22 个逻辑端点，见对照表。）

## 1. 目标与不变量

### 目标

| # | 目标 | 解决现问题 |
|---|---|---|
| G1 | 所有请求经唯一管线，结构上无法绕过 | 两代写法并存（raw `client.send` 绕过通道/传输层） |
| G2 | 服务器差异数据化（`ServerProfile`：`/mk/` vs `/wows/` 前缀、支持类型、特性旗标） | `if (server == RU)` 散落、URI 4 分支重复 |
| G3 | 端点单源：URL / 参数 / 兼容性 / parser / 监控 key 全部来自 Endpoint 定义 | URL 知识散落 40 处 |
| G4 | 映射与聚合分家：门面 1 调用 = 1 请求；多请求编排进 `aggregate` 层、显式 opt-in | `accountInfoDevelopers` 三请求混在门面 |
| G5 | 凭证一等公民：按 种类 × 作用域 建模，缺失语义显式，可扩展 | token 只是字符串参数、静默失败 |
| G6 | 监控自动派生：按 endpoint id 键 | graphql 多 schema 要手写 `SchemaRecorder.key` |

### 不变量（重写不碰）

- 同步 API（异步由调用方线程池/虚拟线程包装）；JDK 21+；Jackson 3；零 HTTP 第三方依赖。
- record 模型 + `parse(JsonNode)` 工厂 + "加字段可读旧数据"的序列化约定；长期缓存用 JSON。
- 共享 HttpClient；gzip/deflate（不声明 br）；`HostPolicy` 按主机的 cookie / 重定向 / 429 策略。
- CN 无官方开发者 API（`WowsServer.CN.api()==false`）；莱服官方 API 走 `/mk/` 前缀 + 307 握手。

## 2. 分层架构

| 层 | 包 | 关键类型 | 职责 |
|---|---|---|---|
| 入口 | `com.shinoaki.wows.api` | `WowsApi` | `of(server)`；不可变 `credentials(...)` |
| 视图 | `...client` | `VortexClient` / `DevelopersClient` / `ClansClient` / `ResourcesClient` | 1 调用 = 1 请求；方法名不带通道后缀 |
| 端点 | `...endpoint` | `Endpoint<T>`、各域 `XxxEndpoints` 常量表 | URL / 参数 / 兼容性 / parser / auth 槽位唯一来源 |
| 管线 | `...transport` | `HttpPipeline` / `Channel` / `HostPolicy` / `ResponseCodec` | 唯一出口：通道头/鉴权 → 主机策略 → 发送 → 解码 |
| 基建 | `...transport` | `HttpClientProvider` | 共享 client；超时 / 代理集中；**不裸暴露给调用方** |
| 凭证 | `...auth` | `Credential` 家族 / `CredentialStore` / `CredentialResolver` | 见 §4 |
| 聚合 | `...aggregate` | `ShipInfoAssembler` / `AccountAssembler` | 多请求编排 |
| 模型 | `...model.*` | record 数据模型（developers / vortex / domain） | 纯数据 + parse |
| 横切 | `...error` / `...monitor` | 异常体系 / 漂移监控 | 见 §6、§7 |

一次调用生命周期：

```
视图方法 → EndpointRequest(server, params)
         → 服务器兼容性检查
         → 凭证解析（发送前 fast-fail）
         → 通道头注入 → 主机策略（cookie/重定向/429）
         → 发送 → 解码（解压/JSON）
         → 监控挂钩（endpoint id）
         → parser → T
```

## 4. 凭证与认证设计

### 4.1 凭证种类

| 种类 | 通道 | 作用域 | 注入 | 说明 |
|---|---|---|---|---|
| `ApplicationId` | dev | 服务器级 | query `application_id` | dev 端点必填槽位；莱服用莱服自己的 key（WG key 无效，已踩坑） |
| `AccessToken` | dev | 账号级 | query `access_token` | OAuth 用户态，解锁 `private.*` 私有数据 |
| `ShareToken` | vortex | 账号级 | query `ac` | 分享凭证，与账号绑定（只对该账号有效） |
| `CookieCredential` | 预留 | 账号级 | 请求头 `Cookie` | 未来 cookie 类认证；**按账号绑定**（与 access_token / share token 同族）；与 WAF cookie（bp_chl）分层，见 4.5 |

```java
// auth 包，每类一个独立小文件（项目无嵌套类约定）
public sealed interface Credential permits ApplicationId, AccessToken, ShareToken, CookieCredential {
    AuthKind kind();                             // kind 决定通道绑定与槽位匹配
    CredentialScope scope();                     // 服务器级 / 账号级（账号级凭证持有绑定 accountId）
    default Map<String, String> queryParams() { return Map.of(); }  // 注入点 1
    default Map<String, String> headers()     { return Map.of(); }  // 注入点 2（cookie 走这里）
    // 所有实现 override toString() 掩码 token（防日志泄漏）
}
```

### 4.2 解析规则（发送前执行）

- **输入**：端点声明的 auth 槽位（`kind` + `Required/Optional`）+ 本次参数（模板含 `{accountId}` 时带账号）。
- **通道过滤**：kind 固定归属通道，vortex 凭证永远不会被注入 dev 端点（反之亦然）。
- **账号级匹配**（`AccessToken` / `ShareToken` / `CookieCredential`）：仅当本次请求的 accountId 与凭证绑定账号一致才注入；不一致视同未配置。现所有需要认证的端点均为账号相关；若未来出现"需要认证但不带 accountId"的端点，再扩作用域维度。
- **服务器级**：整实例通用（实例即服务器；访问多服 = 多个实例，凭证表互不可见，跨服串用结构上不可能）。
- **顺序**：服务器兼容性检查 → 凭证解析 → 发送。CN 上调用 dev 端点直接 `UnsupportedOnServerException`，不查凭证。
- **缺失语义**：
  - `Required` 未命中 → 抛 `MissingCredentialException`（发送前 fast-fail，不产生网络请求）；
  - `Optional` 未命中 → 匿名请求（vortex 公开数据、dev 不带 access_token 即此路径）。
- **覆盖顺序**：调用级 > 实例配置。保留逃生门：`api.vortex().user(accountId, ShareToken.of(accountId, "..."))`。

### 4.3 配置 API（草案）

```java
WowsApi api = WowsApi.of(WowsServer.RU)
        .credentials(c -> c
                .applicationId("...")            // dev · 服务器级
                .accessToken(accountId, "...")   // dev · 账号级（可选）
                .shareToken(accountId, "...")    // vortex · 账号级（可选）
                .cookie(accountId, "..."));      // 预留：cookie 认证（账号级）
```

多账号：同 kind 可配多条，按 accountId 精确命中；账号级凭证对非账号端点（搜索、军团列表等）不注入。

### 4.4 扩展路径（"未来新增认证"怎么落）

1. **新种类**：在 `auth` 包 +1 个 record（实现 kind / 作用域 / 注入映射），端点上声明槽位即可用；sealed + 单一解析器保证不漏处理。
2. **动态凭证**（OAuth 续期、登录换取 cookie）：在 `CredentialStore` 上挂 `CredentialSource` 惰性提供者——**本版只预留接口，不实现**。
3. **注入机制**：现覆盖 query 参数与请求头两类；如未来出现签名等更复杂机制，扩展注入协议即可，端点定义不动。

### 4.5 cookie 与 WAF cookie 的分层

- WAF cookie（`api.korabli.su` 的 `bp_chl` 307 握手）属于传输层，留在 `HostPolicy`，与用户认证无关。
- 用户 cookie 认证是 `CookieCredential`（header 注入、**按账号绑定**，与 access_token / share token 同族）。同请求两者并存时，由 `HostPolicy` 合并为一条 `Cookie` 头。
- cookie 值天然按主机/域生效：注入的目标主机（或通道）在接入实现时由凭证声明；主作用域与其它账号凭证一致（按 accountId 匹配）。

## 6. 错误体系

保留现有四层分类（`BasicException` 基类），新增三类语义：

| 异常 | 时机 | 替代现状 |
|---|---|---|
| `HttpNetworkException`（不变） | 连接/超时/解压失败 | — |
| `HttpStatusException`（不变） | 非 200 / 重定向超限；带 `statusCode` | — |
| `ResponseParseException`（不变） | JSON 非法 / 解析失败；消息带响应摘要 | — |
| `MissingCredentialException`（新） | 必填凭证缺失，发送前 fast-fail | "凭证只是方法参数、漏传就裸发" |
| `UnsupportedOnServerException`（新） | 端点/参数在当前服不支持 | 统一 `IllegalArgumentException` 与"静默空表"两种旧行为 |
| `RateLimitPolicy`（新，非异常） | `STRICT`（默认抛 429）/ `TOLERANT`（返回空+注明） | `searchUserVortexCn` 隐藏行为 → 显式策略参数 |

原则：**同种失败 = 同种异常；"空结果"只表示服务器明确返回了空。**

## 9. 迁移与验收（3.0 断代版）

- **Phase 2 · 全端点迁移**：离线自检（全部）+ 在线 smoke（vortex / dev 双测试类）全绿；测试凭证注入从环境变量读入后构造 `WowsApi`（沿用 TestConfig 思路）。

- **验收原则不变**：新旧实现逐端点逐服对比解析结果（沿用 `ShipInfoCrossSourceTest` 方法）；失败分支用本地假上游验证，不打真实服务。

## 11. 执行记录（2026-10-13 · `rewrite/3.0` 分支）

### Phase 0 ✅ 行为对照表

- 落地 `docs/重写Phase0-行为对照表.md`：29 个请求发送点 → 22 个逻辑端点 × 5 服 × 异常策略的验收清单。

### Phase 1 ✅ 底座 + account 域垂直贯通

- **传输底座收敛**：新增 `transport.HttpClientProvider`（共享 client / 超时 / 代理的唯一持有者）、
  `transport.HostPolicy`（cookie·重定向·429 按主机策略，自 `HttpTransport` 逐字迁移）、
  `transport.ResponseCodec`（状态码校验 + gzip/deflate 解码）；旧 `HttpCodec` / `HttpTransport` 改为**委托**（行为零变化，旧自检全绿）。
- **新架构**：`WowsApi`（不可变入口 + `credentials(...)`）、`server.ServerProfile`（主机 + dev 前缀按域 + extra 按服 + CN dev 拒绝）、
  `auth`（sealed `Credential` 家族 / 按账号精确匹配的 `CredentialResolver` / 调用级覆盖逃生门）、
  `endpoint`（`Endpoint` 注册表 + `EndpointRequest` + `RateLimitPolicy`）、`transport.HttpPipeline`（**唯一出口**）、
  `client.VortexClient` / `client.DevelopersClient`（1 调用 = 1 请求）、`aggregate.AccountAssembler`（3 请求编排）。
- **端点**：`vortex.account.search` / `vortex.account.info` / `dev.account.search` / `dev.account.info` /
  `dev.clan.account` / `dev.clan.info`（6 个）。
- **错误体系**：新增 `MissingCredentialException` / `UnsupportedOnServerException`（+2 枚举码），
  语义变更（503 显式策略、IAE→显式拒绝、静默空表→显式异常）逐条记录在对照表 §4。
- **验证**：离线等价 `RewriteAccountEquivalenceTest` **49/49**（假上游 + raw 回放，含失败分支/限流/gzip/监控键）；
  在线 `RewriteAccountSmokeTest` **16/16**（ASIA/RU/CN 新旧逐端点序列化**逐字节一致**）；
  全部既有离线自检（异常体系 / 序列化兼容 / 三个 field_coverage / 监控 selftest）回归通过。

### Phase 2 ✅ 其余 16 端点全部迁入（战舰 / 军团 / 排行 / 箱子 / 资源 / 词典）

- **端点模型扩展**：`Endpoint` 增加 `servers`（端点级支持面，RU 徽章显式拒绝）/ `notFoundEmpty`（CN 404→空，旧语义保留）/
  `body`（POST 请求体渲染，graphql 三端点）；`throttleEmpty` 从构造参数改为 wither；`QueryParam.render` 携带已解析凭证 →
  新增 `CredentialParam`（`in_garage=1` 跟随 access_token）；`Parser` 三参（携带 `ServerProfile`，军团解析按服区分 mk_ladder）；
  管线补 POST 与 404 语义；查询串统一 `key=value`（空值也带 `=`，对齐旧排行 URL）。
- **ServerProfile/WowsApi**：新增 `ladderRealm`（CN/RU=global、ASIA=sg、EU=eu、NA=us）与 `withPtServer()`；`WowsApi.pt()`。
